# 全骨科三項功能擴充更新包

本包基於你 2026-10-12 上傳的版本及已完成的腰痛更新製作。
這是增量更新，放回現有 `0930` 專案使用，不是獨立新專案。

## 更新內容

- 現有題庫全部 12 種流程：頸椎、腰椎、肩關節、肘腕、髖關節、膝關節、足踝、外傷、兒童、骨骼腫塊、高壓氧評估與未明部位。
- 共 130 個題庫項目，依回答跳過不適用追問，不再受到原本 4 題上限限制。
- 示範知識共 60 筆，每類 5 筆，已包含原本腰痛 5 筆，並非另加 60 筆。每筆都有來源與待醫師確認標示。
- RAG 依本次問診部位篩選示範知識，保留原有基礎知識及診所自訂知識。
- 每類看診前摘要都能顯示病患自述、規則提示、未確認問題、不適用追問、過去預約與最多 5 筆先前問診。
- 表單／聊天／後端共用同一套流程；表單連不到挑題 API 時也保留本地分支規則。
- 篩檢題固定保留；診所端可查看分支、依部位篩選示範知識，仍可編輯自訂題目與知識。

所有醫療內容均為 AI 整理的示範草稿，待實際診所醫師確認，沒有冒稱完成醫師訪談或審核。題庫各類別是原系統分類，不是完整人體解剖分類。腫塊不是癌症診斷，高壓氧是評估／轉診需求，不代表本診所具備設備。

## Windows 啟用步驟

1. 後端命令視窗按 Ctrl+C。先備份現有程式資料夾。
2. 解壓縮本包，將檔案放進原本 `C:\Users\USER\Desktop\0930`，選擇取代同名檔案。
3. 特別確認新增的 `clinical_protocols.json` 與 `clinical_demo.py` 跟 `app.py` 在同一層，不要多包一層資料夾。
4. 保留你原本的 `.env`（不要清空或重填）、`index.css`、`vector_store.db`、`vectorizer.pkl`、LINE 程式、`agent_llm.py`、`rag_generate.py`、`set_admin_password.py`、SQL 以及其他沒有在本包的檔案。不要刪除原專案只保留這個包。
5. 啟動：

```bat
cd /d C:\Users\USER\Desktop\0930
python -m uvicorn app:app --reload
```

6. 重新開啟 `index.html`，按 Ctrl+F5 更新前端。
7. 管理頁：
   - http://127.0.0.1:8000/api/admin/clinic
   - http://127.0.0.1:8000/api/admin/today
   使用原本的管理員帳密登入。

本次不需要新增 SQL。既有 Supabase 病患／掛號／問診資料表與診所自訂資料表仍按原專案設定使用；自訂題目／知識管理仍需之前的 `sql/005_clinic_customization.sql`。本包不更改帳密、LINE 設定或資料庫資料。
LINE worker 與 ngrok 按原本方式開啟。

## 啟動後應看到

如果原本 63 筆向量庫仍在，日誌應顯示基礎知識 63 筆、示範知識 60 筆，診所自訂筆數以你 Supabase 的實際資料為準。
「已載入 Supabase 連線設定」只代表設定可用；請實際登入／讀取資料，才能證明資料庫可存取。原本的 `.env` 已成功，不必再次換金鑰。

## 如何展示三項功能

詳見 `各部位測試與醫師確認.md` 的逐部位題庫與分支。

- 問診：輸入「我膝蓋痛」或「我手腕麻」，第一題應是對應警訊，依回答會追問不同內容。
- 知識：診所設定 → 診所知識庫，按部位篩選，可看到該類 5 筆示範內容。完成問診後展開檢索片段，確認實際來源。
- 摘要：測試病患完成問診並掛號後，到今日看診清單選「預約日」；不一定是今天。查看已回答、未確認、不適用追問與歷史資料。

## 限制與後續確認

- 未回答、不確定或略過不等於沒有警訊。關鍵字規則不理解所有自由敘述，沒有命中規則不代表安全或確診。
- 問診資料只在確認掛號後沿用原程式儲存。中途離開、未掛號或因警訊中止，不會獨立儲存正式問診紀錄。
- 過去預約不代表完成就診；本包沒有創造正式病歷、診斷或處方。
- 指定醫師／略過問診仍保留；如果訊息有明確警訊，會先提醒就醫。沒有提供問診內容時，不能推斷症狀已安全排除。
- 歷史問題目前仍依代碼對應文字，尚未做完整問題版本快照。大幅修改題意時用新代碼，避免混用歷史答案。
- 自訂題庫不能移除示範必要題目；兩項篩檢題文字固定，避免編輯後失去規則意義。追問分支與正負選項需同步經醫師確認。
- 要停用示範知識，把 `clinic_demo_knowledge.json` 相應項目的 active 改為 false 並重啟。醫師確認的診所實際版本可在診所設定新增，註明確認者、日期與來源。
